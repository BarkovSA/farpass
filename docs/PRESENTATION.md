# 📊 FarPass — Презентация для руководства

## Зачем нам FarPass?

### Одна фраза

> **FarPass** — это бесплатный, уже работающий инструмент, который закрывает одну из самых частых дыр в кибербезопасности: передачу паролей открытым текстом.

---

## 🔴 Проблема: как у нас сейчас передаются пароли?

| Способ | Что не так |
|--------|-----------|
| Slack / Teams | Пароль **навсегда** в истории чата. Доступен всем участникам канала. Бэкапы Slack хранятся годами. |
| Email | Пароль в **бэкапах**, пересылках, автодополнении. Почтовые серверы логируют всё. |
| Jira / Confluence | Пароль в тикете = доступ у всей команды, истории изменений, экспортов. |
| Google Docs | Общие документы с паролями — мечта аудитора (и злоумышленника). |
| Стикер на мониторе | Без комментариев. 😅 |

### Что говорят стандарты?

- **ISO 27001** (A.9.2.4): Секретная аутентификационная информация должна передаваться безопасным способом
- **NIST SP 800-63B**: Пароли не должны передаваться по незащищённым каналам
- **152-ФЗ**: Персональные данные (в т.ч. учётные записи) требуют защиты при передаче

---

## 🟢 Решение: FarPass

### Как это работает (30 секунд)

```
Отправитель                          Получатель
     │                                    │
     │  1. Вводит пароль в браузере       │
     │  2. Браузер ШИФРУЕТ (PGP/AES-256) │
     │  3. Получает одноразовую ссылку    │
     │                                    │
     │  ──── отправляет ссылку ────►      │
     │                                    │
     │                4. Открывает ссылку  │
     │                5. Видит пароль      │
     │                6. Ссылка УДАЛЕНА    │
     ▼                                    ▼
```

**Ключевое**: сервер **НИКОГДА** не видит открытый пароль. Шифрование — в браузере. Ключ — только в URL-фрагменте (не отправляется на сервер).

## 🛡️ Аргументы для ИБ-отдела

### Почему это безопасно?

| Свойство | Реализация |
|----------|------------|
| **End-to-End шифрование** | PGP (AES-256) — золотой стандарт. Шифрование В БРАУЗЕРЕ, сервер не видит открытый текст |
| **Zero-knowledge** | Ключ расшифровки — в URL-фрагменте (#), который браузер НЕ отправляет серверу |
| **Одноразовость** | Секрет удаляется после первого просмотра |
| **Автоудаление** | Даже непрочитанные секреты удаляются по TTL (1ч / 1д / 1нед) |
| **Нет учётных записей** | Нечего взламывать — нет пользователей, паролей, сессий |
| **Нет логов содержимого** | Сервер логирует только UUID и метаданные, никогда — содержимое |
| **Минимальная поверхность атаки** | Distroless-образ Docker (без shell, без утилит) |
| **Open Source** | Код открыт, можно аудитировать |

### Чего FarPass НЕ делает (и это правильно)

- ❌ Не хранит историю секретов
- ❌ Не привязывает секреты к пользователям
- ❌ Не создаёт бэкапы (секреты — одноразовые, это by design)
- ❌ Не требует интеграции с AD/LDAP/SSO

## 📈 Что мы получаем?

### Немедленно

- Сотрудники перестанут кидать пароли в Slack/почту
- Каждая переданная «секретная» ссылка — это пароль, который **не остался** в логах

### В перспективе

- Соответствие требованиям ИБ-аудитов
- Культура безопасной передачи данных
- Один инструмент для всех: от разработчиков до HR
